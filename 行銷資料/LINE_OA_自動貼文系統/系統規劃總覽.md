# 第一章｜專案理解

## 1.1 核心目標
建立一套「可持續、可擴充、合規、高質感」的 LINE 官方帳號自動化內容發布系統。
系統需做到：
- 自動蒐集靈感 → 自動生成文案 → 自動生成圖片 → 自動送審 → 自動或人工發布
- 每 2 小時輪播一次內容節奏
- 全程合規，避免違反台灣《食品安全衛生管理法》、《藥事法》、《消費者保護法》等相關法規

## 1.2 品牌調性定位
| 面向 | 定義 |
|------|------|
| 視覺 | 東方養生 × 現代簡約 × 柔和療癒 × 高質感 |
| 語氣 | 溫暖專業、親切不說教、知識型不浮誇 |
| 核心主張 | 草本智慧 × 現代保健 × 身心平衡 |
| 禁止調性 | 誇大療效、迷信宣傳、低質感直銷感 |

## 1.3 法規背景
- **一條根**：保健品，非藥品，非醫療器材
- 適用法規：《食品安全衛生管理法》第 28 條（食品廣告不得宣稱醫療效能）
- 保健食品廣告：不得宣稱「預防、改善、緩解、治療疾病」
- 中醫、五行、太極內容：作為「文化知識 / 養生觀念」分享，非醫療宣稱

# 第二章｜內容策略總體規劃

## 2.1 發文頻率建議（重要評估）

### 每 2 小時發文的風險分析
| 面向 | 風險評估 |
|------|---------|
| 粉絲反感度 | 高。LINE OA 訊息直接推播，頻率過高易被封鎖 |
| 封鎖率 | 每日 10+ 則可能導致封鎖率上升 30-50% |
| 演算法影響 | LINE OA 無演算法篩選，所有訊息強制推送 |
| 對比標準 | 一般品牌 LINE OA 建議每日 1～3 則 |

### 兩套版本建議

**【版本 A：嚴格版（強烈建議）】**
- 每 2 小時自動「產出草稿 + 生成圖片」，但不立即發送
- 每日選出 3～4 則人工確認後發送
- 發送時間：07:00 / 12:00 / 19:00（可選加 21:00）
- 優點：粉絲體驗好、封鎖率低、品質可控
- 適合期：**正式上線建議使用此版**

**【版本 B：強推版（測試階段）】**
- 每 2 小時自動發送
- 建議僅限早 06:00 ～ 晚 22:00（9 個時段）
- 加強合規審查，全自動模式
- 風險：封鎖率高，適合「測試期 / 活動期 / 短期衝高曝光」

## 3.3 各節點詳細規格

### 節點 1：SCHEDULER
- **觸發方式：** n8n Cron（`0 */2 * * *`）
- **輸入：** 當前時間
- **輸出：** `{ timestamp, scheduled_slot, content_pillar }`

### 節點 2：DUPLICATE CHECKER
- **功能：** 查詢 Content Queue 近 7 天已發布 / 草稿主題
- **輸入：** `content_pillar, topic_keywords`
- **輸出：** `{ is_duplicate: bool, suggested_angle }`
- **資料來源：** Google Sheets「Published Posts」表

### 節點 3：TOPIC SELECTOR
- **功能：** 根據時段對應表 + 主題輪播規則，選出本次主題
- **輸入：** `scheduled_slot, content_pillar`
- **輸出：** `{ topic_id, topic_name, sub_category, keywords[] }`
- **資料來源：** Topic Library（Google Sheets）

### 節點 4：TREND FINDER
- **功能：** 搜尋近期相關熱門內容
- **輸入：** `topic_keywords`
- **API 呼叫：** SerpAPI + Google Trends + Perplexity
- **輸出：** `{ trend_sources[], titles[], hooks[], structures[], cta_patterns[] }`
- **注意：** 僅擷取結構與觀念，不複製文字

### 節點 5：KNOWLEDGE GATHERER
- **功能：** 蒐集正確知識素材（衛教資料、中醫文獻、官方健康資訊）
- **輸入：** `topic_keywords`
- **來源：** 衛福部官網、中醫藥資訊網、公開學術資料庫
- **輸出：** `{ facts[], references[], safe_statements[] }`

### 節點 6：CONTENT PLANNER
- **功能：** 決定本次貼文的角度、結構、長度
- **輸入：** `topic, trend_data, knowledge_data`
- **LLM Prompt：** 見附錄 A
- **輸出：** `{ angle, structure, target_emotion, hook_type, format_type }`

### 節點 7：COPY GENERATOR
- **功能：** 生成完整文案（短版 + 長版 + 圖卡版）
- **Model：** Claude claude-sonnet-4-6
- **輸入：** Content Plan + 品牌語氣指引 + 合規規則
- **輸出：** `{ title, hook, short_copy, full_copy, card_copy, cta, hashtags }`

### 節點 8：COMPLIANCE CHECKER
- **功能：** 雙重合規審查
  1. 關鍵詞黑名單比對（即時）
  2. Claude 語意合規判斷（LLM）
- **輸入：** 所有文案內容
- **輸出：** `{ pass: bool, risk_level: low/medium/high, flags[], revised_suggestions[] }`
- **FAIL 處理：** 高風險 → 人工審核；中風險 → 自動修改後重審；低風險 → 加免責聲明

### 節點 9：IMAGE PROMPT GENERATOR
- **功能：** 根據文案主題生成 Midjourney / DALL-E Prompt
- **Model：** Claude claude-sonnet-4-6
- **輸出：** `{ prompt_1_1, prompt_4_5, prompt_line, style_tags[], negative_prompts[] }`

### 節點 10：IMAGE GENERATOR
- **API：** Midjourney API / OpenAI DALL-E 3
- **輸入：** Image Prompts
- **輸出：** `{ image_url_square, image_url_portrait, image_url_line }`
- **儲存：** Google Drive / Cloudinary

### 節點 11：LAYOUT FORMATTER
- **功能：** 組裝成 LINE Messaging API 可用格式
- **輸出格式：** Flex Message JSON / Image Message + Text Message
- **輸出：** `{ line_message_payload, preview_text, image_url, publish_time }`

### 節點 12：DRAFT SAVER
- **儲存位置：** Google Sheets「Draft Posts」+ Notion 草稿庫
- **輸出：** `{ draft_id, status: "pending_review" }`

### 節點 13：HUMAN REVIEW GATE
- **介面：** Notion Database 審核頁面 / Google Forms
- **欄位：** 草稿預覽、合規狀態、核准/拒絕、修改意見
- **通知：** LINE 通知到管理員（透過 Messaging API）
- **超時處理：** 4 小時未審核 → 自動保留草稿（不發送）

### 節點 14：LINE PUBLISHER
- **API：** LINE Messaging API（Broadcast Message）
- **輸入：** 核准的 Line Message Payload
- **輸出：** `{ message_id, sent_at, status }`

### 節點 15：LOG / ARCHIVE
- **儲存：** Published Posts 表
- **記錄：** 發布時間、內容 ID、圖片 URL、合規狀態

### 節點 16：PERFORMANCE TRACKER
- **資料來源：** LINE OA Insights API
- **追蹤指標：** 開封率、點擊率、封鎖率、互動數
- **更新頻率：** 每日一次
- **Dashboard：** Google Sheets 自動圖表

保證、絕對、100%、第一名、最強、無敵、
